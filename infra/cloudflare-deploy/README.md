# `cloudflare-deploy`

Terraform module that materializes per-app deploy attachments
(Worker custom domains, and future targets) from `deploy:` blocks
declared in each consuming project's `project.cue`. Generated by
`shaka deploy generate-tf`; the substrate (`main.tf`, `variables.tf`,
backend) is hand-written.

## Layout

- `terraform/main.tf` — Cloudflare provider declaration. No resources
  or data sources live here; everything that depends on app
  configuration is generated.
- `terraform/variables.tf` — `cloudflare_account_id` (literal, passed
  through `TF_VAR_cloudflare_account_id`).
- `terraform/backend.tf` — `Linode` Object Storage remote backend,
  generated by `shaka object-store tfstate emit`.
- `terraform/generated/` — generator-owned. One `<project>.tf` per
  app with a `deploy:` block, plus `_zones.tf` aggregating one
  `data "cloudflare_zone"` per unique zone referenced across all
  deploys. When a project declares `deploy.cache`, its `<project>.tf`
  also carries a zone-level `cloudflare_ruleset` for the
  `http_request_cache_settings` phase. Carries a "Do not edit by
  hand" header; drift is caught by `shaka deploy generate-tf --check`
  in `shaka preflight`.

## Building

```
nix develop . --command just validate
```

runs the same `tofu validate` / `nix fmt --check` / whitespace steps
CI runs for this project (via `shaka preflight`).

## Provisioning

Apply prerequisites: the consumer apps' Worker scripts must already be
deployed (the `cloudflare_workers_custom_domain` resource references
the Worker by service name). For the portfolio, that's handled by
`wrangler deploy` in `apps/kolohelios-portfolio/`.

```
cp .env.example .env       # `.env` is gitignored
op run --env-file=.env -- just plan
op run --env-file=.env -- just apply
```

`.env.example` documents the full shape; the Cloudflare provider
auto-detects `CLOUDFLARE_API_TOKEN` from the environment.

### Remote state

State is held in the shared `kolohelios` `Linode` Object Storage
bucket under `tfstate/cloudflare-deploy/terraform.tfstate`. The
backend is declared by `terraform/backend.tf`, which is generated by
`shaka object-store tfstate emit --module infra/cloudflare-deploy/terraform`
(re-run if the namespace changes; do not edit by hand).

To run `tofu` against the remote backend, export the bucket-scoped S3
credentials minted by `shaka object-store init`:

```
export AWS_ACCESS_KEY_ID=<from 1Password / GH secret TFSTATE_ACCESS_KEY>
export AWS_SECRET_ACCESS_KEY=<from 1Password / GH secret TFSTATE_SECRET_KEY>
```

If migrating an existing local state into the remote backend, run
`shaka object-store tfstate migrate --module infra/cloudflare-deploy/terraform`
once after the credentials are exported — it wraps
`tofu init -migrate-state`.
